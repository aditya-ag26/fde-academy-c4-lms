# `docs/09-design-notes/`

Why this is shaped the way it is. For whoever builds or inherits this next.

| Document | What it is |
|---|---|
| `BUILD-INSTRUCTIONS.md` | The phased build plan this repository was constructed from |
| `LMS-STRUCTURE.md` | The structural design: what goes where and why |
| `drive-layer-design.md` | How content reaches the repo from Drive, without git |

These are **design records, not living documentation**. They capture decisions and the
reasoning behind them, including options that were considered and rejected. When the
implementation and a design note disagree, the implementation is what is true — but the
note still tells you what the original intent was, which is usually the thing you
actually need when deciding whether to change something.

Operational documentation lives in the numbered folders above.
