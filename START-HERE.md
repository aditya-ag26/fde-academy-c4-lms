# Start here

Ten minutes, once, before the first session. You will not need to read it twice.

---

## What this is

A GitHub repository used as the course platform. Three things live here:

| | |
|---|---|
| **The material** | Sessions, pre-reads, reference documents. Plain files you read in the browser. |
| **Discussions** | Where you ask, answer, and submit. This is where you actually spend your time. |
| **The dashboard** | The [front page](README.md) — what's on this week, what's due. It updates itself. |

You do not need to install anything. You do not need to know git.

---

## You have read access. That is on purpose.

You cannot push files to this repository, and you will never need to.

**Everything you do happens in Discussions** — asking a question, submitting an
assignment, getting reviewed, answering someone else. Read access is all that requires.

There is a real reason behind it, beyond permissions:

> A thread captures your approach, the wrong turn, and the correction.
> A file upload captures only the final artefact.

The thread is the deliverable. That is also why the submission form asks for your
approach **before** your result — an approach written afterwards is a reconstruction of
one.

## Where does this go?

The single most useful table in this document. Post in the wrong place and your
question takes longer to answer.

| What you have | Where it goes |
|---|---|
| A question about a specific session | **Doubts - Session** (names the session) |
| A general question, not tied to one session | **Q&A** |
| An assignment to hand in | **Assignments** (use the form) |
| A coding question solution | **Coding Questions** |
| Something you built and want to show | **General** |
| Practice you did that wasn't required | **Self work & Practice** |
| Can't log in, tool won't install, access problem | **Help Desk** |
| Feedback about the batch itself | **Feedback** |
| A document here is **wrong or broken** | An [issue](../../issues/new/choose), not a Discussion |

The last row is the only exception to "everything is a Discussion". An issue is a
**defect with a fix and a closed state**. A question is not a defect.

## How to get a good answer

1. **Say what you already tried.** This is the single thing that turns "I don't get it"
   into something answerable. It also means nobody wastes your time suggesting the thing
   you did twenty minutes ago.
2. **Say where it broke down**, not just that it did. "I understood up to the embedding
   step, then lost the plot at reranking" gets a targeted answer.
3. **Paste the actual error.** Not a description of the error.
4. **Use the form fields.** They are not bureaucracy — they are what lets the bot label
   and route your thread before a human reads it.

## Answering other people counts

It is one of the most useful things you can do here, and it is genuinely how you find
out whether you understood something.

Threads labelled **`good-first-answer`** are ones a peer can handle. Start there.

---

## Two kinds of answer

Both can appear on the same thread, and they mean different things:

| | Who | Means |
|---|---|---|
| **Marked** ✓ | You, on your own thread | This solved *my* problem |
| **Verified** ✓✓ | Staff | This is *correct* |

An answer can be marked but not verified — it worked, for the wrong reason. Worth
knowing when you are reading old threads.

**Mark the answer when your thread is resolved.** It takes a second, and it is what
makes the thread useful to the next person who searches for the same problem.

## The bot

It replies quickly to confirm your submission registered, checks your form fields, and
labels the thread. That first acknowledgement matters — without it you would have no way
to know your submission went through.

Commands you can use in a comment:

| Command | Does |
|---|---|
| `/staff` | Escalates to staff. Use it when a thread has stalled. |
| `/status` | Shows your own progress |
| `/rubric` | Posts the rubric for the linked activity |
| `/resolved` | Marks your own thread resolved |

**The bot does not answer questions.** If it ever appears to, that is a bug —
[bot-policy.md](docs/02-delivery/bot-policy.md) states exactly what it will and will not
do.

## One thing that will confuse you otherwise

Assignment briefs exist in **two places**: a file in `activities/briefs/`, and a
Discussion thread.

> **The file is canonical. The thread is a published copy of it.**

If they ever disagree, the file is right — and that is a bug worth reporting. Never
assume the thread is the newer version.
